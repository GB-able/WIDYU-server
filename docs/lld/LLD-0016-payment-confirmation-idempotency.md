## 목적

동일 주문의 병렬 승인 요청이 외부 PG를 중복 호출하지 않도록, 승인 시작 시 주문 행을 비관적 쓰기 락으로 조회한다.

## 범위

- `PaymentService.confirmPayment()`가 사용하는 주문 조회에 `PESSIMISTIC_WRITE` 락을 적용한다.
- 먼저 락을 얻은 요청만 `CREATED` 상태에서 PG 승인과 내부 반영을 진행한다.
- 대기한 요청은 커밋 뒤 갱신된 주문 상태와 기존 `Payment`를 확인해 기존 결제 결과를 반환한다.

## 제외 범위

- PG 호출과 DB 트랜잭션 경계 분리
- PG 성공 후 내부 반영 실패 보정
- 취소 멱등성 및 다중 인스턴스 배치 정책

## 인수조건

- [x] 결제 주문 조회는 비관적 쓰기 락으로 수행된다.
- [x] 승인 완료 뒤 동일 주문·동일 paymentKey 재요청은 기존 결제 정보를 반환한다.
- [x] 기존 API 계약과 DB 스키마는 유지된다.
- [x] `./gradlew :backend:widyu-api:test`가 통과한다.

## 미결정 사항

- Toss 승인 API 재호출 계약과 PG 성공 후 내부 반영 실패 보정 정책은 LLD-0015의 후속 과제로 유지한다.
