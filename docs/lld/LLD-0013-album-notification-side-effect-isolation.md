# LLD-0013: 앨범 알림 부수효과 격리

> Low-Level Design. 이 문서는 해당 기능 구현과 PR 본문의 **오라클(ground truth)** 이다.

## 1. 목적 / 배경

앨범 생성·조회·댓글·좋아요·잠금해제 이벤트는 앨범 쓰기 흐름 이후 보호자 또는 시니어에게 FCM 알림을 보내기 위한 후속 처리다.
FCM 런타임 실패가 앨범 쓰기 트랜잭션이나 API 결과를 덮어쓰지 않도록, 앨범 알림 이벤트를 커밋 이후 처리하고 FCM 발송 실패를 리스너 내부에서 격리한다.

## 2. 범위

### In scope

- 변경 모듈: widyu-api
- `AlbumNotificationListener`의 앨범 이벤트 핸들러를 커밋 이후 이벤트 처리로 전환한다.
- FCM 발송 호출 중 런타임 예외가 발생하면 warn 로그만 남기고 전파하지 않는다.
- 커밋 이후 트랜잭션이 없는 상태에서도 필요한 알림 대상 데이터를 조회할 수 있도록 지연 로딩 의존을 낮춘다.
- 기존 필수 데이터 조회 실패 예외 정책은 유지한다.
- 단위 테스트로 커밋 이후 이벤트 핸들러 선언과 FCM 실패 격리를 고정한다.

### Out of scope

- FCM outbox, 메시지 큐, 재시도 워커 도입
- 알림 이벤트 DTO 패키지 이동
- FCM 알림 문구 변경
- DB 스키마 변경
- 앨범 접근 정책 변경

## 3. 인터페이스 / API

기존 API 계약 변경 없음.

- 앨범 업로드, 조회, 댓글, 좋아요, 잠금해제 API 응답 계약은 변경하지 않는다.
- FCM 알림 payload 제목, 본문, 카테고리, image 정책은 기존 값을 유지한다.

## 4. 데이터 모델

DB 스키마 변경 없음.

Repository 조회 보강:

- 시니어 회원의 가족 ID를 scalar로 조회한다.
- 보호자 회원의 가족 ID를 scalar로 조회한다.
- 잠금해제 알림에서 앨범 작성자를 fetch 조회한다.

## 5. 처리 흐름

`AlbumNotificationListener`

1. 앨범 이벤트 핸들러는 `AFTER_COMMIT` 단계에서 실행된다.
2. 테스트나 트랜잭션 없는 발행 경로를 위해 fallback 실행은 허용한다.
3. 이벤트별로 기존과 동일하게 알림 제목·본문·수신자를 계산한다.
4. 필수 회원 또는 앨범을 찾지 못하면 기존처럼 `BusinessException`을 던진다.
5. `fcmService.sendMessageToUser()` 호출은 안전 발송 helper를 통해 수행한다.
6. FCM 발송 호출이 런타임 예외를 던지면 warn 로그만 남기고 다음 수신자 또는 리스너 종료 흐름을 유지한다.

가족 대상 알림:

1. 작성자가 시니어이면 `SeniorProfile` 기준 가족 ID를 조회한다.
2. 가족의 보호자 목록을 조회해 각 보호자에게 기존 앨범 알림 DTO를 발송한다.
3. 작성자가 보호자이면 보호자의 가족 ID를 조회한다.
4. 가족의 시니어 목록을 조회해 각 시니어에게 기존 앨범 알림 DTO를 발송한다.

## 6. 예외 / 에러 처리

- 알림 이벤트의 필수 회원이 없으면 기존 `NOTIFICATION_MEMBER_NOT_FOUND` 예외를 유지한다.
- 잠금해제 알림의 대상 앨범이 없으면 기존 `ALBUM_NOT_FOUND` 예외를 유지한다.
- FCM 발송 중 런타임 예외는 warn 로그만 남기고 전파하지 않는다.
- FCM 전달 재시도는 수행하지 않는다.

## 7. 인수조건 (Acceptance Criteria)

- [x] 앨범 생성·조회·댓글·좋아요·잠금해제 이벤트 핸들러는 커밋 이후 이벤트 처리로 선언된다.
- [x] 트랜잭션 없는 테스트 발행 경로에서도 앨범 이벤트 핸들러를 실행할 수 있다.
- [x] FCM 발송 중 런타임 예외가 발생해도 앨범 알림 리스너는 예외를 전파하지 않는다.
- [x] 여러 수신자 중 한 명의 FCM 발송이 실패해도 다음 수신자 발송 시도를 계속한다.
- [x] 알림 대상 회원 또는 앨범이 없을 때의 기존 `BusinessException` 정책은 유지된다.
- [x] `./gradlew :backend:widyu-api:test`가 통과한다.

## 8. 영향 범위 / 마이그레이션

- DB 스키마 변경 없음.
- API 계약 변경 없음.
- 앨범 이벤트 알림 실행 시점이 커밋 이후로 이동한다.
- FCM 발송 실패 시 알림 유실 가능성은 기존처럼 남지만 앨범 쓰기 흐름과 분리된다.
