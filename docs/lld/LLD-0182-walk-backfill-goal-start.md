## 1. 목적 / 배경

앱은 연동할 때마다 건강 앱에서 최근 7일 걸음 수를 읽고, 기기 DB에 "서버에 보낸 값"이 없는 날짜를 모두 `POST /api/v1/goals/walks/sync`로 하루씩 보낸다. 새 기기 로그인, 재설치, 휴대폰 교체처럼 기기 DB가 비면 최근 7일이 한꺼번에 온다.

2026-11-20 21:33 개발 서버에서 이 경우가 생겼다. 11-17에 가입하고 11-20 04:47에 걷기 목표 500보를 처음 정한 시니어의 새 iPhone이 11-14부터 11-20까지 7일을 2초 안에 보냈다.

기록이 없던 지난 날짜의 목표는 "그 날짜 뒤 첫 기록의 목표"로 정한다(`WalkService.goalForNewRecord`, #1003). 목표를 바꾼 경우를 위한 규칙인데, 목표가 아예 없던 날짜까지 11-20의 500보를 붙였다. 그래서 가입 전 날짜(11-14~16)를 포함한 11-14~19에 기록과 25P, 목표 달성 알림(G01)이 생겼다. 시니어와 보호자가 같은 알림을 7개 받았다.

## 2. 범위

### In scope
- 변경 모듈: widyu-api(`WalkService.updateSteps`)
- 목표 시작일보다 앞선 날짜는 기록, 포인트, 알림 없이 받는다.

### Out of scope
- 앱의 7일 재전송 동작. 밀린 날짜를 살리는 의도된 동작이라 유지한다.
- 목표 시작일 이후 지난 날짜의 달성 알림. 지금처럼 날짜마다 G01을 발행한다. 목표를 정한 뒤 며칠 밀렸다가 연동하면 그 날짜 수만큼 알림이 간다. 줄이는 방식은 따로 정한다.
- 이미 잘못 만들어진 기록, 포인트 정리. 운영 데이터가 없고, 개발 서버 정리는 별도로 한다.
- 목표 시작일 컬럼 추가. 아래 5절의 기존 기준으로 충분하다.

## 3. 인터페이스 / API

`POST /api/v1/goals/walks/sync` 계약은 그대로다.

| 상황 | 이전 | 이후 |
| --- | --- | --- |
| 목표 시작일보다 앞선 날짜, 기록 없음 | 기록 생성, 달성 시 포인트와 G01 | 200 `achieved=false`, 기록, 포인트, 알림 없음 |
| 목표 시작일 이후 날짜 | 기록 생성, 달성 시 포인트와 G01 | 같음 |
| 목표를 정한 적 없음, 기록 없음 | 400 | 같음 |

목표 시작일 이전 날짜에 400을 주지 않는 이유: 앱은 2xx가 아니면 그 날짜를 재시도 대상으로 남겨 연동마다 다시 보낸다. 200을 받으면 보낸 것으로 기록하고 멈춘다.

## 4. 데이터 모델

변경 없음.

## 5. 처리 흐름

1. 그날 기록을 비관적 잠금으로 읽는다(LLD-0119).
2. 기록이 없으면:
   1. 목표를 정한 적 없으면 400(기존).
   2. 목표 시작일을 구한다. 목표를 처음 정하면 그날 기록이 생기므로(`setOrUpdateGoal`) **이 회원의 첫 기록 날짜**다(`findFirstByMemberOrderByWalkDateAsc`). 기록이 없으면 오늘이다. 월별 조회의 미수신 날짜 계산(`countMissingGoalDays`)과 같은 기준이다.
   3. 요청 날짜가 목표 시작일보다 앞서면 로그만 남기고 `achieved=false`로 끝낸다.
   4. 아니면 기존처럼 `goalForNewRecord`의 목표로 기록을 만든다.
3. 걸음 수 갱신, 달성 판정, 포인트 1회 지급, G01 발행은 기존과 같다.

목표 시작일 이전 기록은 2-3 단계 때문에 새로 생기지 않으므로 "첫 기록 날짜 = 목표 시작일"이 계속 유지된다.

## 6. 예외 / 에러 처리

새 예외 없음. 목표 시작일 이전 날짜는 INFO 로그(`목표 시작 전 날짜의 걸음 수는 기록하지 않음`)를 남긴다.

## 7. 인수조건 (Acceptance Criteria)

- [x] 목표 시작일보다 앞선 날짜를 연동하면 걷기 기록 저장, 포인트 지급, G01 발행이 없고 응답은 `achieved=false`다.
- [x] 목표 시작일 이후 지난 날짜를 처음 연동해 달성하면 기록이 생기고 포인트 1회와 G01 1건이 생긴다.
- [x] 오늘 처음 목표를 정한 시니어의 기기가 최근 7일(6일 전~오늘)을 순서대로 보내면 새 기록은 0건, 포인트는 오늘 기록의 1건, G01은 `G01:W:<오늘 walkId>` 1건이다.
- [x] 재연동 중복 방지, 걸음 수 감소 방지 등 기존 걷기 테스트가 통과한다.

## 8. 영향 범위 / 마이그레이션

- DB, API 계약, 앱 변경 없음.
- 이미 잘못 생긴 기록이 있는 회원은 그 기록이 첫 기록이 되어 목표 시작일로 쓰인다. 개발 서버의 해당 계정은 별도로 정리한다.

## 9. 미결정 사항 (Open Questions)

- 목표 시작일 이후 밀린 지난 날짜가 여러 개 달성될 때 알림을 줄일지(오늘만 알림, 묶음 알림 등).
