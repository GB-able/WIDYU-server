## 1. 목적 / 배경

결제 승인·취소는 외부 PG 호출과 내부 결제·포인트 반영을 하나의 서비스 트랜잭션에서 수행한다.
외부 PG 성공 뒤 내부 포인트 반영이 실패하면 외부 결제 상태와 내부 상태가 달라질 수 있으므로, 후속 보정 설계 전에 현재 호출 순서와 예외 전파를 테스트로 고정한다.

## 2. 범위

### In scope

- 변경 모듈: widyu-api
- 승인·취소에서 PG 호출 성공 후 포인트 서비스가 실패할 때 예외가 전파되는 현재 동작을 테스트한다.
- 승인·취소에서 PG 호출이 실패하면 내부 결제 저장 또는 포인트 반영을 시도하지 않는 현재 동작을 테스트한다.

### Out of scope

- 결제 상태 모델, DB 스키마, API 계약 변경
- PG 재호출, 보정 작업, 대사 절차 구현
- 승인·취소 멱등성 및 동시성 보강

## 3. 처리 흐름

승인:

1. PG 승인 호출이 성공하면 내부 `Payment` 저장과 포인트 적립을 시도한다.
2. 포인트 적립이 실패하면 예외가 호출자에게 전파된다. PG 승인 호출은 이미 완료된 상태다.
3. PG 승인 호출이 실패하면 내부 `Payment` 저장과 포인트 적립은 시도하지 않는다.

취소:

1. PG 취소 호출이 성공하면 내부 취소 상태 반영과 포인트 환수를 시도한다.
2. 포인트 환수가 실패하면 예외가 호출자에게 전파된다. PG 취소 호출은 이미 완료된 상태다.
3. PG 취소 호출이 실패하면 포인트 환수는 시도하지 않는다.

## 4. 인수조건

- [x] PG 승인 성공 후 포인트 적립 실패 경로가 테스트로 재현된다.
- [x] PG 승인 호출 실패 시 내부 결제 저장과 포인트 적립을 시도하지 않는다.
- [x] PG 취소 성공 후 포인트 환수 실패 경로가 테스트로 재현된다.
- [x] PG 취소 호출 실패 시 포인트 환수를 시도하지 않는다.
- [x] `./gradlew :backend:widyu-api:test`가 통과한다.

## 5. 미결정 사항

- Toss 승인·취소 API의 동일 요청 재호출 계약
- PG 성공 뒤 내부 반영 실패를 복구할 재조회·보정 작업의 운영 정책
