# LLD-0122: 큰 센서 묶음이 와도 WebSocket 연결을 끊지 않고, 상한 초과는 대기열 앞에서 거절하기

> Low-Level Design. 이 문서는 해당 기능 구현과 PR 본문의 **오라클(ground truth)** 이다.

## 1. 목적 / 배경

센서 묶음 본문 상한은 32KB다(`sensor.max-payload-bytes`, LLD-0041). 그런데 WebSocket 세션의 텍스트 메시지 상한은 16,640자다. Tomcat 기본값은 8,192자이고, Spring STOMP가 세션을 열 때 16KB + 256자(`StompSubProtocolHandler`의 최소값)로 올린다. SockJS와 STOMP로 감싼 메시지가 이 값을 넘으면 Tomcat이 `closeCode 1009`(메시지 너무 큼)로 세션 전체를 닫는다. 실제 SockJS 클라이언트로 재 보니 원문 16,384바이트는 통과하고 16,500바이트부터 끊겼다. LLD-0041은 WebSocket으로 보낸 묶음이 REST와 같은 결과를 내야 한다고 정했지만, 약 16.4~32KB 묶음은 WebSocket에서 거절도 저장도 되지 않고 연결만 끊긴다.

2026-11-05 개발 서버에서 회원 29의 연결이 13:24~13:33에 20번 넘게 끊겼다(6시간 동안 1009 종료 38회). 연결이 흔들린 뒤 앱이 밀린 IMU를 여러 초짜리 합본으로 보내면 16KB를 넘고, 끊긴 뒤 재연결하는 동안 묶음이 또 커지는 일이 반복됐다. 그 연결로 가던 심박, 위치, ACK도 함께 멈췄고 13:24, 13:28 구간 IMU는 저장되지 않았다.

### 버퍼 크기 근거

개발 DB `sensor_batch`의 IMU 묶음 785,528건(2026-10-22~11-05)을 샘플 수로 회귀했다.

- 원문 바이트 ≈ 785 + 22.35 × `acc_n` + 25.81 × `gyro_n` (잔차 p99 179바이트)
- 관측 최대: 충격 묶음 31,452바이트(가속도 668, 자이로 667, 상한의 96%), 합본 가속도 999개(20초)
- 가속도와 자이로 각 1,000개인 20초 합본은 약 49KB다
- SockJS 클라이언트 프레임(`["SEND\n...\u0000"]`)과 STOMP 헤더로 감쌀 때 늘어나는 양은 약 221바이트이고 샘플 수와 무관하다. 샘플이 숫자 배열이라 이스케이프할 따옴표가 머리 필드(약 112개)에만 있다

버퍼는 64KB(65,536자)로 둔다.

| 기준 | 필요 크기 | 64KB |
| --- | --- | --- |
| 본문 상한 32KB 묶음이 서버까지 도착 | 32,768 + 약 221 | 충족 |
| 앱이 만들 수 있는 최대 합본(약 49KB)도 연결을 끊지 않음 | 약 49KB + 221 | 충족 |
| Spring STOMP 메시지 상한(`messageSizeLimit`) | 기본 64KB | 같음. 더 키우면 Spring에서 막힌다 |

33KB처럼 본문 상한에 딱 맞추면 32KB를 넘는 합본이 올 때 지금처럼 연결 전체가 끊긴다. 64KB면 그 묶음이 컨트롤러까지 도착해 그 묶음만 `REJECTED`로 거절되고 연결은 유지된다.

### 대가

- Tomcat은 세션마다 텍스트 버퍼를 세션 상한 크기로 잡는다. 문자(2바이트) 단위라 세션당 약 33KB(16,640자)에서 128KB(65,536자)가 된다. 개발 서버 동시 세션은 최대 2개였다(`WebSocketMessageBrokerStats`). 1,000세션이어도 128MB로, 기본 힙(호스트 메모리의 25%, 개발 약 1.4GB)의 약 9%다.
- 본문 상한 검사가 센서 대기열 뒤(`SensorBatchService`)에만 있으면, 32~64KB 묶음이 대기열 500칸을 차지한 뒤에야 거절된다. 대기열 메모리 상한이 LLD-0091의 16MB(32KB × 500)에서 32MB로 늘어난다. 그래서 검사를 수신 스레드로 당긴다.

## 2. 범위

### In scope
- 변경 모듈: widyu-api
- Tomcat WebSocket 텍스트 메시지 버퍼 64KB, STOMP 메시지 상한도 같은 상수로 명시
- WebSocket 센서 컨트롤러가 대기열에 넣기 전에 본문 상한을 검사하고 넘으면 `REJECTED` ACK

### Out of scope
- 본문 상한 32KB 자체. 정책서 v1.1 B 합의 대기 A의 권고안("한 메시지는 32KB 이하")이며 앱과 맞춘 계약이다. 바꾸려면 앱팀, 정책서 담당과 정한다(9절).
- 바이너리 메시지 버퍼. STOMP over SockJS는 텍스트 프레임만 쓴다. 버퍼는 세션마다 미리 잡히므로 쓰지 않는 쪽은 키우지 않는다.
- WebSocket 메시지 속도 제한. 버퍼와 별개 과제다.
- REST 경로. Tomcat 커넥터 본문 상한(기본 2MB)이 32KB보다 크고 상한 검사는 지금처럼 서비스가 한다.

## 3. 인터페이스 / API

API 계약은 바뀌지 않는다. WebSocket `/app/sensor/batches/send`의 상한 초과 응답만 바뀐다.

| 본문 크기 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 약 16.4KB 이하 | 처리 | 처리 |
| 약 16.4KB 초과 ~ 32KB | 연결 종료(1009) | 처리 |
| 32KB 초과 ~ 64KB | 연결 종료(1009) | `/user/queue/sensor/result`에 `{batchId, seq, result: REJECTED}`, 연결 유지 |
| 64KB 초과 | 연결 종료(1009) | 연결 종료(Spring STOMP 상한 또는 Tomcat 버퍼) |

상한 초과 묶음에서 `batch_id`와 `seq`를 읽지 못하면 지금의 검증 실패와 같이 `/user/queue/errors`로 간다(LLD-0041 5.2).

## 4. 데이터 모델

변경 없음.

## 5. 처리 흐름

1. `WebSocketConfig.configureWebSocketTransport`가 STOMP 메시지 상한(`messageSizeLimit`)과 세션 텍스트 상한을 같은 상수(64KB)로 둔다. 세션 상한은 핸들러 decorator가 연결 직후 `setTextMessageSizeLimit`로 올린다. STOMP가 16,640자로 올리는 것과 같은 방식이다. `ServletServerContainerFactoryBean`으로 컨테이너 기본값을 바꾸는 방법은 서블릿 컨테이너가 없는 `@SpringBootTest`(MOCK) 컨텍스트를 시작하지 못하게 해서 쓰지 않는다.
2. `SensorBatchWebSocketController.ingestBatch`(수신 스레드)가 수신 시각을 잡은 뒤 본문 길이를 `sensor.max-payload-bytes`와 비교한다.
3. 넘으면 원문에서 `batch_id`, `seq`만 얕게 읽어 `REJECTED` ACK를 발신 세션에 보내고 돌아온다. 센서 실행기에 작업을 넘기지 않는다.
4. 넘지 않으면 지금처럼 센서 실행기에 넘긴다. 서비스의 상한 검사는 REST 경로를 위해 그대로 둔다.

## 6. 예외 / 에러 처리

새 에러 코드 없음. 상한 초과는 기존 `SENSOR_BATCH_TOO_LARGE`로 기록한다.

| 경우 | 응답 |
| --- | --- |
| 상한 초과, 식별자 읽힘 | `REJECTED` ACK, WARN `센서 배치 거절: ... code=SENSOR_4001 ...` |
| 상한 초과, 식별자 없음 또는 JSON 아님 | `/user/queue/errors` (`@MessageExceptionHandler`) |

## 7. 인수조건 (Acceptance Criteria)

- [ ] AC1: 17KB 센서 묶음(변경 전 1009로 끊기던 크기)을 SockJS로 보내면 연결이 유지되고 `STORED` ACK를 받는다.
- [ ] AC2: 본문 상한과 같은 크기의 묶음을 SockJS로 보내면 연결이 유지되고 `STORED` ACK를 받는다. 본문 상한을 올리고 버퍼를 그대로 두면 이 테스트가 실패한다.
- [ ] AC3: 본문 상한을 넘는 49KB 묶음을 보내면 연결이 유지되고 `REJECTED` ACK를 받으며, 센서 실행기 작업 수가 늘지 않는다.
- [ ] AC4: 상한 초과 묶음에 식별자가 없으면 서비스를 부르지 않고 예외가 수신 스레드에서 전파된다.
- [ ] `./gradlew :backend:widyu-api:test`가 통과한다.

## 8. 영향 범위 / 마이그레이션

- 세션당 Tomcat 텍스트 버퍼 메모리 약 33KB → 128KB. Tomcat은 메시지를 받을 때 버퍼 크기가 세션 상한과 다르면 새로 잡는다.
- 앱 변경 없이 배포할 수 있다. 앱은 지금까지 연결 종료를 받던 8~32KB 묶음에 `STORED` ACK를, 32KB 초과 묶음에 `REJECTED` ACK를 받는다.
- 센서 대기열 메모리 상한은 LLD-0091의 16MB를 유지한다.

## 9. 미결정 사항 (Open Questions)

- 본문 상한 32KB 유지 여부: 충격 묶음이 이미 96%이고 자이로가 있는 20초 합본은 약 49KB다. 앱이 32KB 이하로 나눠 보낼지, 상한을 올릴지 앱팀, 정책서 담당과 정한다. 상한을 올리면 이 문서의 버퍼와 STOMP 상한도 함께 올려야 한다(AC2가 알린다).
- 앱 합본 경로: 정책서 권고안은 소켓으로 1초 묶음만, 밀린 자료와 충격 보강은 HTTP로 보내는 구조다. 앱이 합본을 소켓으로 보내는지, 합본 상한이 20초인지 앱팀 확인이 필요하다.
