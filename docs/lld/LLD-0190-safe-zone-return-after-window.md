## 1. 목적 / 배경

어르신이 안심구역으로 돌아왔는데 보호자에게 「안심구역을 벗어났어요」가 먼저 오고 곧바로 「안심구역으로 돌아왔어요」가 왔다는 제보가 있었다. 실제로 나간 시점의 이탈 알림은 정상이었다.

개발 서버 알림 기록(회원 28): 11-27 09:26 이탈, 돌아옴 없음 → 21:11:53 이탈 → 21:12:06 돌아옴. 회원 37도 12:17:31 이탈, 12:17:33 돌아옴처럼 몇 초 간격의 쌍이 반복된다.

원인: 이탈 알림 뒤 30분 묶음이 끝난 다음 돌아오면 돌아옴 알림을 보내지 않고 상태가 `EXITED`로 남는다. 귀가 직후 경계에서 위치가 한 번 밖으로 튀면 묶음이 끝난 상태라 새 이탈 알림이 나가고, 곧 안으로 들어오면 새 묶음 안이라 돌아옴 알림이 나간다. 보호자는 실제 귀가 소식은 못 받고 가짜 이탈과 돌아옴을 받는다.

## 2. 범위

### In scope
- `SeniorStayState.applySafeZoneTransition`(widyu-domain)의 돌아옴 규칙

### Out of scope
- 이탈 규칙(묶음이 없거나 끝났을 때만 알림)은 그대로다
- 집에 머무르는 중(귀가 30분 뒤) GPS가 경계 밖으로 한 번 튀는 경우. 연속 바깥 횟수나 더 넓은 이탈 반경 같은 이력(hysteresis)은 따로 정한다
- 스키마 변경 없음. `alert_state`, `alert_until` 칸을 그대로 쓴다

## 3. 처리 흐름

| 상태 | 안→밖 | 밖→안 |
| --- | --- | --- |
| 묶음 없음 또는 끝남 | Z01, `EXITED`, `alert_until = now + 30분` | 없음. 단 `EXITED`면 Z02 (변경) |
| `EXITED`, 묶음 안 | 없음 | Z02, `RETURNED`, `alert_until = now + 30분` (변경: 기존은 TTL 유지) |
| `RETURNED`, 묶음 안 | 없음 | 없음 |

- 돌아옴은 상태가 `EXITED`(이탈만 알린 상태)이면 묶음이 끝났어도 한 번 알린다
- 돌아옴을 알리면 그 시각부터 30분 묶음을 다시 연다. 귀가 직후 경계 흔들림의 재이탈, 재진입은 알리지 않는다
- 묶음 안의 재이탈로 이탈 알림이 생략된 뒤(`RETURNED`) 늦게 돌아와도 돌아옴은 없다. 보호자는 그 재이탈을 듣지 못했으므로 돌아옴도 필요 없다

## 4. 인수조건 (Acceptance Criteria)

- [ ] 이탈 알림 뒤 30분이 지나 돌아오면 Z02가 한 번 발행되고 `alert_until`이 돌아온 시각 + 30분이다
- [ ] 늦게 돌아온 직후 경계에서 밖으로 튀었다 들어와도 Z01, Z02가 더 발행되지 않는다
- [ ] 돌아옴 뒤 30분이 지나 나가면 Z01이 다시 발행된다
- [ ] 묶음 안 재이탈은 Z01 0건, 첫 돌아옴 Z02 1건 규칙이 그대로다
- [ ] `SafeZoneAlertServiceTest`, `StayStateOutboxAtomicityTest`가 통과한다

## 5. 배포 영향

- 배포 시점에 `EXITED`이고 묶음이 끝났는데 안심구역 밖에 있는 어르신은 다음 진입 때 돌아옴 알림이 한 번 간다. 이미 안심구역 안에 있으면 안→안 이동이라 알림이 없다. 둘 다 스키마나 데이터 보정이 필요 없다
