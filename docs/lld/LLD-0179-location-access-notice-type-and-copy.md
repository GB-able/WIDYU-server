# LLD-0179: 위치 조회 통보를 알림 종류로 등록하고 문구를 정한다 (L01, L02)

> Low-Level Design. 이 문서는 #1143 구현과 PR 본문의 오라클이다.

| 항목 | 값 |
| --- | --- |
| 상태 | Review |
| Issue | #1143 |
| 관련 ADR | [ADR-0036](../adr/ADR-0036-privacy-records-consent-access-logs.md) 결정 3, 4 |
| 관련 LLD | [LLD-0056](LLD-0056-location-access-log.md), [LLD-0130](LLD-0130-location-access-notice-immediate.md) |
| 작성자 | Claude / feature-1143 |

## 1. 목적 / 배경

보호자가 어르신 위치를 볼 때마다 서버는 어르신에게 통보 푸시를 보낸다(LLD-0130). 이 푸시는 알림 종류(`NotificationType`)가 없는 옛 형식이라 다음 문제가 있었다.

- 문구가 제목 「위치 조회 알림」, 본문 「{이름}님이 내 위치를 확인했어요」뿐이다. 위치정보법 제19조 3항이 통보에 담으라고 한 세 가지(제공받는 자, 제공 일시, 제공 목적) 중 목적이 없고, 일시는 알림센터 행 시각으로만 알 수 있다.
- 알림 종류가 없어 우선순위, 채널, 보관 기간 규칙을 받지 못한다. 옛 형식은 FCM 기본값으로 나간다.

위듀(어르신) 알림 정책서 v12는 두 알림(즉시, 모아 알림)을 「미정」으로 두고 「위치기반서비스 신고 내용과 맞춰 정하기」를 추천한다. 신고서 원문이 저장소에 없어, 이번에는 법 조문과 저장소의 동의 항목(`GUARDIAN_LOCATION_PROVIDE`, 「보호자에게 위치 제공」)을 근거로 서버가 문구를 정한다(사용자 위임, 2026-11-19).

## 2. 범위

### In scope
- widyu-domain: `NotificationType`에 `LOCATION_ACCESS_NOTICE`(L01), `LOCATION_ACCESS_DIGEST`(L02) 추가
- widyu-api: `NotificationCopy`에 L01, L02 문구와 시각 문구 함수 `clockText` 추가. 건강일정 리스너의 같은 함수를 이것으로 옮긴다
- `LocationAccessLogService`(열람마다 즉시 통보), `LocationAccessDigestSender`(서버 시작 시 한 번 요약)가 새 종류와 문구로 보낸다

### Out of scope
- 법정 단위(10회, 10일, 20일, 30일) 모아서 통보(LLD-0130 Out of scope 그대로)
- 위듀 앱의 위치 조회 기록 화면. 지금 앱 경로에 없어 딥링크는 비운다
- 이미 쌓인 옛 형식 알림센터 행의 문구 변경

## 3. 인터페이스 / API

API 변경 없음. 어르신이 받는 푸시와 알림센터 행이 바뀐다.

| 코드 | 언제 | 제목 | 부제목 |
| --- | --- | --- | --- |
| L01 | 보호자가 위치를 볼 때마다 | {보호자 이름} 님이 내 위치를 확인했어요. | {오전/오후 시각}에 가족 안부 확인을 위해 위치를 봤어요. |
| L02 | 서버 시작 1분 뒤, 남은 미통보 기록 요약 | 보호자가 내 위치를 확인했어요. | {시작 날짜}부터 보호자 {보호자 수}명이 가족 안부 확인을 위해 {횟수}회 봤어요. |

- 시각은 정책서 공통 규칙 3(「오전/오후 N시 M분」, 정각은 「오후 3시」)을 따른다. 기준은 열람 기록의 `accessedAt`이다.
- 시작 날짜는 요약에 든 기록 중 가장 이른 `accessedAt`의 「M월 d일」이다.
- 보호자 이름을 찾지 못하면 기존처럼 「보호자」로 채운다. 이름이 없다고 통보를 거르지 않는다.

**법정 항목 대응**

| 항목(제19조 3항) | L01 | L02 |
| --- | --- | --- |
| 제공받는 자 | 제목의 보호자 이름 | 보호자 수만. 이름은 열람 기록 조회 API(`/location/access-logs/mine`)에 있다 |
| 제공 일시 | 부제목 시각, 알림센터 행 시각 | 시작 날짜. 건별 일시는 열람 기록 조회 API |
| 제공 목적 | 「가족 안부 확인」 | 「가족 안부 확인」 |

L02는 LLD-0130의 배포 직후 1회 정리 경로라 평소에는 나가지 않는다. 요약이라 건별 항목이 빠지는 한계는 LLD-0130 6절과 같다.

## 4. 데이터 모델

테이블 변경 없음. 알림센터 행(`fcm_notification`)의 `type` 칸에 새 값 두 개가 들어간다. 이 칸은 VARCHAR라 ALTER가 필요 없다.

| 종류 | 칩 | 전달 | 우선순위 | 설정 그룹 | 보관 | 딥링크 |
| --- | --- | --- | --- | --- | --- | --- |
| `LOCATION_ACCESS_NOTICE` | 기타 | 푸시+센터 | 보통(INTERACTION) | NONE | 90일 | 없음 |
| `LOCATION_ACCESS_DIGEST` | 기타 | 푸시+센터 | 보통(INTERACTION) | NONE | 90일 | 없음 |

- **설정 그룹 NONE:** 법정 통보라 끌 수 없다. 어르신 스위치는 어차피 켜짐 고정이지만(LLD-0095), 그룹을 NONE으로 두어 보호자 스위치 개편(#1137)과도 무관하게 한다.
- **보통 우선순위:** 조용히(PASSIVE)는 APNs 우선순위 5로 나가 iOS가 전원 상태에 따라 늦게 전달할 수 있다. 법은 즉시 통보를 요구하므로 APNs 10으로 나가는 보통을 쓴다. 옛 형식도 FCM 기본값(APNs 10)이었으므로 도달 속도는 그대로다. 대신 소리가 나는 기본 채널이라, 보호자가 홈을 자주 열면 어르신 폰이 자주 울리는 부담은 남는다(LLD-0130 8절과 같은 한계).
- **칩:** 정책서 1절 「기타」. 옛 행은 `FcmCategory.LOCATION_NOTICE`로 기타 칩에 묶이고(`NotificationCenterFilter.ETC.legacyCategories`), 새 행은 종류의 `centerFilter`로 묶인다. 같은 칩에 함께 보인다.

## 5. 처리 흐름

1. `LocationAccessLogService.record`가 열람 기록을 저장한다(변경 없음).
2. `notifyImmediately`가 L01 문구를 만들고 `FcmSendDto.of(LOCATION_ACCESS_NOTICE, ...)`로 접수한다. `relatedMemberId`는 보호자다(같은 가족 확인, 변경 없음). `notified_at`을 채운다(변경 없음).
3. `LocationAccessDigestSender.send`는 선점 뒤 L02 문구로 한 건을 접수한다. 선점과 롤백은 그대로다.

eventId는 무작위다. 즉시 통보는 열람 한 건에 한 번만 불리고, 요약은 조건부 선점이 중복을 막는다.

## 6. 예외 / 에러 처리

- 문구 필수 값이 비면 `NotificationCopy`가 예외를 던진다. 보호자 이름은 「보호자」로 채우고 시각과 숫자는 항상 있으므로 정상 경로에서는 나지 않는다.
- 즉시 통보 실패 처리는 기존과 같다. `REQUIRES_NEW` 안이라 조회 트랜잭션에 영향이 없고, 호출부가 예외를 잡는다(LLD-0056).

## 7. 인수조건 (Acceptance Criteria)

- [ ] 열람마다 `LOCATION_ACCESS_NOTICE` 한 건이 접수되고 제목에 보호자 이름, 부제목에 열람 시각과 「가족 안부 확인」이 들어간다.
- [ ] 보호자 이름이 없으면 「보호자」로 채워 보낸다.
- [ ] 요약은 `LOCATION_ACCESS_DIGEST`로 가장 이른 열람 날짜, 보호자 수, 횟수, 목적을 담는다.
- [ ] 두 종류는 기타 칩, 푸시+센터, 보통, NONE, 딥링크 없음이다.
- [ ] 건강일정 문구의 시각 표기가 그대로다(`clockText` 이동).
- [ ] verify.sh가 통과한다.

## 8. 영향 범위 / 마이그레이션

- DB 마이그레이션 없음. 이미 쌓인 옛 행은 옛 문구 그대로 기타 칩에 남는다.
- 어르신 앱은 새 `notificationType` 값 두 개를 받는다. 딥링크가 없으므로 누르면 앱 기본 동작(알림센터)이다.
- 법률 자문을 거친 문구가 아니다. 위치기반서비스 신고서의 목적 표현과 다르면 문구표 두 줄만 고치면 된다.

## 9. 미결정 사항 (Open Questions)

- 신고서에 적힌 제공 목적 표현. 받으면 「가족 안부 확인」을 그 표현으로 맞춘다.
