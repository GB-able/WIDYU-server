# LLD-0014: FCM 토큰 소유자 변경 처리

## 1. 목적 / 배경

`MemberFcmToken.token`은 유니크하지만, 같은 기기에서 다른 회원이 로그인하며 기존 토큰을 등록하는 경우가 있다.
현재는 기존 토큰을 비활성화만 해 새 로그인 회원이 해당 기기에서 알림을 받지 못할 수 있다.
토큰은 마지막으로 등록한 회원 한 명에게만 활성 상태로 귀속되도록 한다.

## 2. 범위

### In scope

- 변경 모듈: widyu-api, widyu-domain
- 기존 토큰의 회원이 현재 로그인 회원과 다르면 토큰 행의 소유자를 현재 회원으로 변경하고 활성화한다.
- 기존 토큰의 회원이 현재 로그인 회원과 같으면 기존처럼 토큰을 활성화한다.
- 새 토큰은 기존처럼 새 행으로 저장한다.
- 소유자 변경, 동일 회원 재활성화, 새 토큰 저장을 단위 테스트로 검증한다.

### Out of scope

- 한 기기에서 여러 회원에게 동시에 알림을 보내는 정책
- FCM 토큰 이력 테이블 또는 감사 로그 추가
- FCM 발송 실패 재시도와 토큰 무효화 정책 변경
- API 요청·응답 계약과 DB 스키마 변경

## 3. 인터페이스 / API

기존 API 계약을 유지한다.

- `POST /api/v1/fcm/token/login`
- 요청: `token`, `deviceInfo`
- 응답: 기존 성공 응답 유지

## 4. 데이터 모델

`MemberFcmToken`의 기존 데이터 모델을 유지한다.

- `token` 유니크 제약을 유지한다.
- 기존 토큰 행의 `member_id`를 현재 로그인 회원으로 변경할 수 있도록 도메인 메서드를 추가한다.
- 소유자 변경 시 `active=true`, `expiredAt=null`, `lastUsedAt=현재 시각`으로 갱신한다.

## 5. 처리 흐름

`MemberFcmTokenService.saveOrActivateFcmToken(fcmToken, deviceInfo)`

1. 현재 로그인 회원을 조회한다.
2. 토큰 값으로 기존 `MemberFcmToken`을 조회한다.
3. 기존 토큰이 없으면 현재 회원 소유의 활성 토큰을 새로 저장한다.
4. 기존 토큰의 회원이 현재 회원과 같으면 토큰을 활성화한다.
5. 기존 토큰의 회원이 다르면 기존 토큰 행의 회원을 현재 회원으로 변경하고 활성화한다.

## 6. 예외 / 에러 처리

- 토큰 조회 또는 저장 중 발생하는 기존 영속성 예외 정책을 유지한다.
- 토큰 소유자 변경은 서비스 트랜잭션 안에서 수행한다.
- 동시 등록에 따른 DB 유니크 제약 위반 재시도 정책은 이번 범위에서 변경하지 않는다.

## 7. 인수조건 (Acceptance Criteria)

- [x] 다른 회원 소유의 기존 토큰을 현재 회원이 등록하면 해당 토큰은 현재 회원에게 귀속되고 활성 상태가 된다.
- [x] 현재 회원 소유의 비활성 토큰을 다시 등록하면 토큰은 활성 상태가 된다.
- [x] 처음 등록한 토큰은 현재 회원 소유의 활성 행으로 저장된다.
- [x] 토큰 값 유니크 제약과 기존 로그인 API 계약은 유지된다.
- [x] `./gradlew :backend:widyu-api:test`가 통과한다.

## 8. 영향 범위 / 마이그레이션

- DB 스키마 변경 없음.
- API 계약 변경 없음.
- 같은 기기에서 계정을 전환한 뒤 마지막 로그인 회원이 FCM 알림 수신자가 된다.
