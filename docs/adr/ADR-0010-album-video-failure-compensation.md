# ADR-0010: 앨범 영상 처리 실패 보상 삭제 정책

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-07-21 |
| 관련 | LLD-0012, #424 |

## 맥락 (Context)

영상이 포함된 앨범은 요청 시점에 `PROCESSING` 상태로 저장되고, 영상 압축·썸네일 생성·S3 업로드는 비동기로 수행된다.
비동기 처리 중 일부 파일 업로드가 성공한 뒤 다음 파일이나 썸네일 업로드가 실패하면 앨범은 `DELETED` 상태가 되지만, 이미 업로드된 S3 파일은 남을 수 있다.

## 결정 (Decision)

영상 비동기 처리 실패 시 앨범은 기존처럼 `DELETED` 상태로 전환한다.
실패 전 업로드에 성공한 영상/썸네일 S3 파일은 best-effort로 보상 삭제한다.
보상 삭제 실패는 원래 실패 처리를 덮어쓰지 않고 warn 로그만 남긴다.
비동기 처리에 성공한 경우에만 `AlbumCreatedEvent`를 발행한다.

## 고려한 대안 (Considered Options)

1. **앨범만 `DELETED` 처리하고 S3 파일은 배치 정리** — 구현은 단순하지만 불필요한 S3 오브젝트가 누적될 수 있다.
2. **실패 즉시 업로드 성공분 best-effort 삭제** — 현재 구조에서 추가 인프라 없이 orphan 파일을 줄일 수 있다.
3. **업로드 작업 outbox/worker 도입** — 실패 복구와 재시도에는 유리하지만 현재 범위보다 크다.

## 결과 (Consequences)

### 긍정

- 실패한 영상 앨범이 사용자 피드에 노출되지 않는다.
- 실패 전 업로드된 S3 파일이 즉시 정리되어 저장소 orphan을 줄인다.
- 생성 이벤트는 성공한 앨범에만 발행된다.

### 부정 / 트레이드오프

- 보상 삭제는 best-effort라 S3 삭제 실패 시 파일이 남을 수 있다.
- 서버 재시작으로 비동기 작업 자체가 중단되는 경우는 이번 결정으로 해결하지 않는다.

## 후속 / 미결정

서버 재시작 중 in-flight 작업 복구와 S3 orphan 배치 정리는 별도 설계로 검토한다.
