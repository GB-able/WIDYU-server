# ADR-0009: 안전구역 이탈 알림 원자 중복 차단

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-07-21 |
| 관련 | LLD-0011, #422 |

## 맥락 (Context)

안전구역 이탈 알림은 위치 업데이트 핫패스에서 발생하는 외부 부수효과다.
현재 중복 차단은 Redis `hasKey()`로 플래그 존재를 확인한 뒤 `set()`으로 플래그를 저장한다.
두 요청이 동시에 들어오면 둘 다 플래그가 없다고 판단하고 안전구역 이탈 이벤트를 중복 발행할 수 있다.

## 결정 (Decision)

안전구역 이탈 알림 플래그는 Redis `set-if-absent`와 TTL을 한 번에 적용하는 원자 동작으로 생성한다.
플래그 생성에 성공한 요청만 `SafeZoneExitEvent`를 발행한다.
이미 플래그가 있으면 이벤트를 발행하지 않는다.
안전구역 재진입 시에는 기존 정책대로 플래그를 삭제한다.

## 고려한 대안 (Considered Options)

1. **현재 `hasKey()` + `set()` 유지** — 구현이 단순하지만 병렬 요청에서 중복 이벤트를 막지 못한다.
2. **Redis `set-if-absent` + TTL 사용** — 별도 인프라 없이 원자 중복 차단을 제공한다.
3. **영속 outbox 또는 메시지 큐 도입** — 전달 보장과 재시도에는 유리하지만 현재 범위에서는 운영 복잡도가 크다.

## 결과 (Consequences)

### 긍정

- 병렬 안전구역 이탈 요청에서도 30분 안에 이벤트 발행을 한 번으로 제한한다.
- 안전구역 알림 플래그와 이벤트 발행 책임이 별도 서비스로 분리된다.
- 기존 Redis 키와 TTL 정책을 유지한다.

### 부정 / 트레이드오프

- 이벤트 발행 후 FCM 전송 실패 시 재시도나 보상 처리는 여전히 없다.
- Redis 장애 시 위치 업데이트 흐름에 예외가 전파되는 기존 특성은 유지한다.

## 후속 / 미결정

FCM 전송 실패 재시도와 outbox 도입은 알림 유실 문제가 관측되면 별도 설계로 검토한다.
