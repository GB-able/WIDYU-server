# ADR-0011: 앨범 알림 부수효과 격리 정책

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-07-21 |
| 관련 | LLD-0013, #426 |

## 맥락 (Context)

앨범 생성, 조회, 댓글, 좋아요, 잠금해제는 앨범 상태 변경이 주 목적이고 FCM 알림은 후속 부수효과다.
현재 앨범 이벤트 리스너가 동기 이벤트로 FCM 발송을 호출하면 FCM 런타임 실패가 앨범 쓰기 흐름에 영향을 줄 수 있고, 커밋되지 않은 앨범 상태에 대해 알림이 먼저 발송될 수도 있다.

## 결정 (Decision)

앨범 이벤트 알림은 트랜잭션 커밋 이후 처리한다.
FCM 발송 중 런타임 예외가 발생하면 warn 로그만 남기고 리스너 밖으로 전파하지 않는다.
알림 대상 조회에 필요한 앨범·회원 데이터가 없으면 기존 `BusinessException` 정책을 유지한다.
전달 보장을 위한 outbox, 메시지 큐, 재시도 워커는 이번 결정 범위에서 제외한다.

## 고려한 대안 (Considered Options)

1. **기존 동기 이벤트 유지** — 구현 변경은 없지만 FCM 실패가 앨범 쓰기 흐름에 영향을 줄 수 있다.
2. **커밋 이후 이벤트 처리와 FCM 실패 격리** — 추가 인프라 없이 앨범 쓰기와 알림 부수효과의 실패 경계를 분리할 수 있다.
3. **outbox 또는 메시지 큐 도입** — 전달 보장과 재시도에는 유리하지만 현재 범위보다 운영 복잡도가 크다.

## 결과 (Consequences)

### 긍정

- 앨범 쓰기 흐름은 FCM 런타임 실패와 분리된다.
- 커밋된 앨범 상태를 기준으로 알림을 발송한다.
- 알림 실패가 발생해도 원래 앨범 API 성공/실패 판단을 덮어쓰지 않는다.

### 부정 / 트레이드오프

- FCM 발송 실패 시 자동 재시도나 전달 보장은 없다.
- 커밋 이후 리스너에서 조회한 데이터 기준으로 알림을 구성하므로, 커밋 직후 데이터가 변경되면 최신 조회 결과가 반영될 수 있다.

## 후속 / 미결정

FCM 전달 보장, 실패 재시도, outbox 도입은 알림 유실 문제가 관측되면 별도 설계로 검토한다.
