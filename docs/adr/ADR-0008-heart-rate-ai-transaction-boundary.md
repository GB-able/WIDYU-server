# ADR-0008: 심박 AI 판정과 저장 트랜잭션 경계 분리

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-07-20 |
| 관련 | LLD-0010, #420 |

## 맥락 (Context)

심박수 배치 처리(`HeartRateService.processHeartRates`)는 외부 AI 서버 호출과 Redis/JPA 저장을 하나의 `@Transactional` 메서드에서 수행한다.
AI 서버 지연이나 장애가 DB 트랜잭션 점유 시간으로 이어지고, AI 실패 시 원본 심박 기록을 저장할지 여부도 코드와 테스트에 명시되어 있지 않다.

## 결정 (Decision)

AI 이상 판정 호출은 저장 트랜잭션 밖에서 수행한다.
AI가 성공하면 판정 결과를 명시적 입력으로 저장 전용 서비스에 전달하고, 저장 전용 서비스의 public `@Transactional` 메서드에서 `HeartRateResult`, `HeartRateEvent`, `HeartRateEmergency`를 저장한다.
AI 실패 시에는 기존 동작을 유지하여 원본 심박 기록을 저장하지 않고 예외를 전파한다.

## 고려한 대안 (Considered Options)

1. **현재 구조 유지** — 변경량이 적지만 외부 네트워크 대기와 DB 트랜잭션이 계속 결합된다.
2. **AI 실패 시 원본 심박 기록만 저장** — 장애 상황에서도 원본 이력을 보존할 수 있지만, 제품 정책과 응답 계약이 미확정이라 이번 PR 범위를 넘는다.
3. **AI 호출 후 짧은 저장 트랜잭션으로 분리** — 현재 실패 정책을 유지하면서 트랜잭션 점유 시간을 줄이고 테스트로 경계를 고정할 수 있다.

## 결과 (Consequences)

### 긍정

- 외부 AI 호출 지연이 JPA 저장 트랜잭션을 점유하지 않는다.
- 저장 로직이 별도 서비스의 public `@Transactional` 경계로 이동해 Spring 프록시 self-invocation 문제를 피한다.
- AI 실패 시 저장하지 않는 현재 정책이 AI 실패 정책 테스트로 고정된다.

### 부정 / 트레이드오프

- 회원 존재 확인과 실제 저장 사이에 회원이 삭제되면 AI 호출 후 저장 단계에서 다시 예외가 발생할 수 있다.
- AI 실패 시 원본 심박 기록 유실 가능성은 기존과 동일하게 남는다.

## 후속 / 미결정

AI 미가용 시 원본 심박 기록을 보존해야 하는지는 제품 정책 확인 후 별도 ADR/LLD에서 결정한다.
