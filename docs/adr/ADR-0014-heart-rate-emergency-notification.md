# ADR-0014: 심박 EMERGENCY 보호자 FCM 알림 정책

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-07-26 |
| 관련 | LLD-0020, #448 |

## 맥락 (Context)

심박 AI가 `EMERGENCY`를 판정하면 응급기록은 저장하지만 보호자 알림은 발송되지 않는다.
기존 FCM LLD에는 심박 이상 알림이 명시돼 있어 문서와 구현이 불일치한다.
제품 요구사항은 `EMERGENCY` 즉시 알림, `CAUTION` 후속 검토다.

## 결정 (Decision)

신규 심박 배치가 `EMERGENCY`로 판정돼 저장된 직후, 해당 시니어와 같은 가족의 보호자 전원에게 기존 FCM 서비스로 `HEART_MESSAGE` 알림을 발송한다.
`NORMAL`, `CAUTION`, 중복 배치는 알림을 발송하지 않는다.
기존 배치 시작 시각 멱등성 검사를 통과한 신규 배치만 이 경로에 도달하므로 재전송은 중복 알림을 만들지 않는다.

FCM 장애는 심박 저장 이후의 부수효과 실패로 취급한다. 보호자별 발송 실패는 로그만 남기고 나머지 보호자 발송과 심박 처리 결과에는 영향을 주지 않는다.

## 고려한 대안 (Considered Options)

1. **`CAUTION`도 즉시 알림** — 경고 빈도와 문구 정책이 확정되지 않아 과도한 알림 위험이 있다.
2. **신규 FCM 카테고리와 알림 설정 그룹 추가** — 별도 사용자 설정 요구사항이 없어 기존 `HEART_MESSAGE`로 충분하다.
3. **도메인 이벤트·아웃박스·재시도 큐 도입** — 외부 호출 안정성은 높지만 현재 FCM 공통 정책의 범위를 넘어선다.

## 결과 (Consequences)

### 긍정

- EMERGENCY 발생을 보호자에게 즉시 전달한다.
- 기존 가족 조회와 FCM 발송 경로를 재사용한다.
- 배치 재전송에 따른 중복 알림을 막는다.

### 부정 / 트레이드오프

- FCM 실패는 재시도하지 않아 알림이 유실될 수 있다.
- `HEART_MESSAGE` 카테고리에 수동 메시지와 자동 긴급 알림이 함께 저장된다.

## 후속 / 미결정

`CAUTION`의 빈도 기반 알림, 긴급 알림 전용 설정 및 FCM 재시도는 제품 요구사항이 확정될 때 별도로 결정한다.
