# ADR-0044: 위치는 Redis에 두고 신선도를 드러내며, 체류와 안전구역 판정 상태는 MySQL에서 알림과 함께 커밋한다

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Proposed |

## 맥락 (Context)

위치 한 건은 Redis 최신 위치, Redis 이동 경로, Redis 체류 정보, Redis 안전구역 알림 표식, MySQL 알림 Outbox를 함께 바꾼다.

- **신선도:** 최신 위치는 4분마다 만료만 늘어나 몇 시간 전 좌표도 남는다(LLD-0140 이후 본문은 그대로다). 그런데 응답의 `updatedAt`은 응답을 만든 시각이라 오래된 좌표가 방금 갱신된 것처럼 보인다. 이동 경로 점은 저장 시각만 있고 15분 거르기가 없다.
- **판정 상태와 알림의 원자성:** 체류는 DB 커밋 뒤 Redis에 저장하고(LLD-0058), 30분 알림 묶음은 Redis SETNX/Lua로 잡은 뒤 롤백 콜백으로 되돌린다. 알림 Outbox는 MySQL 트랜잭션에 들어간다. 커밋 직후 프로세스가 죽거나 Redis 쓰기가 실패하면 상태와 알림이 어긋날 수 있다(LLD-0121 Out of scope 1번, "전이 상태 DB 영속화" 후속으로 남겨 둔 일).

## 결정 (Decision)

1. **최신 위치와 이동 경로는 Redis에 둔다.** 자주 바뀌고 오래될수록 쓸모가 줄며, 보호자 조회가 잦다. TTL 연장은 본문을 바꾸지 않는다.
2. **좌표를 내보낼 때 신선도를 함께 싣는다.** 측정 시각(앱이 보낸 값), 서버 수신 시각, 출처(`LATEST`, `STAY`, `REQUEST`), 경과 초. `updatedAt`의 뜻은 "응답 생성 시각"으로 문서에 바로잡고 값은 그대로 둔다(기존 클라이언트 호환). "몇 분 지나면 오프라인" 같은 기준은 서버가 정하지 않는다.
3. **체류, 안전구역 전이, 30분 알림 묶음의 권위 있는 저장소를 MySQL `senior_stay_state`로 옮긴다.** 위치 처리 트랜잭션 안에서 상태와 알림 Outbox를 함께 바꿔 함께 커밋하거나 함께 롤백한다. Redis 표식과 롤백 보정은 없앤다.
4. **같은 자리 위치는 상태를 쓰지 않는다.** 잠그지 않고 읽어 30m 안이면 끝낸다. 바꿀 때만 행을 잠그고(`SELECT ... FOR UPDATE`) 다시 읽어 판정한다. 같은 회원 처리 순서는 JVM 순서 잠금(LLD-0139)이 맡고, DB 행 잠금과 PK는 상태 변경의 마지막 방어선이다.
5. **전환은 서버 시작 때 예전 Redis 상태를 한 번 옮긴다.** 비어 있는 행만 채우고 Redis 키는 지우지 않는다.

## 고려한 대안 (Considered Options)

1. **Redis에 상태를 두고 Lua로 상태와 표식을 한 번에 바꾸기:** Redis 안에서는 원자적이지만 MySQL Outbox와 한 번에 커밋되지 않는다. 지금 문제의 핵심이 그 경계라 기각.
2. **상태 변경을 Outbox처럼 DB에 쓰고 Redis에 비동기로 반영(상태는 Redis에서 계속 읽기):** 판정이 여전히 Redis를 읽어 지연된 반영과 판정이 어긋난다. 기각.
3. **위치마다 상태 행을 UPDATE(마지막 위치까지 DB에 저장):** 구현은 단순하지만 평시 위치마다 쓰기와 잠금이 생긴다. 같은 자리 판정은 읽기만으로 충분해 기각. 최신 위치는 Redis로 충분하다.
4. **최신 위치까지 MySQL로 옮기기:** 위치마다 DB 쓰기가 늘고 Redis의 TTL 만료 장점을 잃는다. 기각.

## 결과 (Consequences)

### 긍정
- 이탈, 복귀 상태와 알림이 함께 커밋된다. 커밋 직후 사망이나 Redis 장애로 상태와 알림이 어긋나지 않는다.
- 판정 트랜잭션 안의 Redis 명령이 없어져 Redis 지연이 DB 커넥션 점유로 번지지 않는다(LLD-0121의 남은 체류 GET, 표식, 커밋 후 체류 저장).
- 보호자 화면과 서버 소비자가 좌표의 나이를 알 수 있다.

### 부정 / 트레이드오프
- 위치마다 PK 조회 1건이 MySQL에 늘어난다(예전에는 Redis GET). 전이 때 잠금 조회와 쓰기가 붙는다. 측정은 LLD-0141 10절.
- 다중 인스턴스에서 같은 회원 첫 상태를 동시에 만들면 한쪽이 PK 충돌로 롤백된다(재전송으로 회복). 단일 인스턴스에서는 JVM 순서 잠금이 막는다.
- 앱이 새 필드를 읽기 전까지 화면은 그대로다.

## 후속 / 미결정
- 오래된 위치를 화면에서 어떻게 보일지, 몇 분부터 "오래됨"으로 볼지(제품 결정).
- 경계 흔들림 완화(연속 N점, 히스테리시스)는 별도 안전구역 분석 뒤 결정한다. 이 ADR은 저장소만 옮긴다.
