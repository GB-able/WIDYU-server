# ADR-0045: 위치 원본을 새로 저장하지 않고, 위치 ACK는 실시간 처리 결과를 말한다

> Architecture Decision Record. 하나의 중요한 의사결정과 그 이유를 기록한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |
| 날짜 | 2026-11-13 |
| 관련 | LLD-0143, #1047. 대체: ADR-0030의 위치 원본 보존 적용, ADR-0041 결정 2(위치 ACK의 저장 확인) |

## 맥락 (Context)

v2 위치 한 건마다 원문을 `location_fix`에 새로 저장하고(LLD-0048), ACK는 그 저장 결과(`STORED`, `DUPLICATE`)로 정했다(LLD-0123, ADR-0041 결정 2). 이 때문에 위치 수신 경로에 실시간 처리와 원본 저장의 실패 분리, 유일 키 경합 복구, 원본 전용 트랜잭션, 회차 귀속 조회가 붙었다(LLD-0139). 실증 회차 내보내기, 관리자 `location.csv`, 활동 상태의 차량 판정(`IN_VEHICLE`)이 이 행을 읽는다는 설명을 들은 뒤, 사용자는 제거 방향을 다시 정했다.

## 결정 (Decision)

1. **위치 원본의 신규 영구 저장을 실증 회차까지 포함해 중단한다.** 회차만 예외로 남기거나 기능 플래그로 숨기지 않는다. 별도 영속 큐나 S3 원본 저장으로 대체하지 않는다.
2. **과거 자료는 그대로 둔다.** `location_fix` 테이블과 행, 조회, 내보내기, 보관 기간 정리, 탈퇴 삭제는 바꾸지 않는다.
3. **위치 ACK는 실시간 처리 결과를 말한다.** `APPLIED`(반영), `SKIPPED`(정상 생략), `REJECTED`(요청 오류). 저장하지 않고 `STORED`라고 답하지 않는다. 기술 오류와 대기 초과는 ACK 없이 재전송을 받는다. ACK는 보호자 수신 보장이 아니다.
4. **입력 규칙은 그대로 받는다.** v2 필드 검증, 본인 확인, 시니어 확인은 유지한다. 회차 필드는 받되 쓰지 않는다.
5. 심박, IMU 원본 수집은 바꾸지 않는다.

## 고려한 대안 (Considered Options)

1. **실증 회차에만 원본 저장 유지:** 회차 귀속, 실패 분리, 저장 ACK 복잡성이 그대로 남는다. 사용자가 기본안으로 삼지 말라고 했다.
2. **기능 플래그로 끄기:** 코드 경로가 남아 두 계약을 함께 유지해야 한다.
3. **ACK 결과 이름 유지(`STORED`를 "처리됨"으로 재정의):** 이름과 뜻이 어긋나 과거 기록과 섞이면 저장된 것으로 읽힌다. 현재 앱 develop(33efddb5)은 위치 ACK를 구독하지 않아 이름을 바꿔도 깨지는 소비자가 없다.

## 결과 (Consequences)

### 긍정
- 위치 수신이 원본 저장 트랜잭션과 커넥션을 쓰지 않는다. 위치 한 건의 DB 접근은 판정(시니어 확인, 체류 상태)과 상태가 바뀔 때의 쓰기, 알림 Outbox만 남는다.
- ACK가 실제로 일어난 일을 말한다.

### 부정 / 트레이드오프
- **잃는 분석 가능성:** 새 회차의 `location` 스트림, 관리자 `location.csv`의 신규 구간, 위치 속도로 하던 `IN_VEHICLE` 판정(기본 꺼짐), 정확도와 속도, 모의 위치 여부 같은 원본 필드의 사후 분석. 최신 위치와 15분 경로(Redis)만 남는다.
- 원본 중복 행으로 하던 멱등이 사라진다. 같은 위치의 재전송은 최신 시각 비교로 `SKIPPED`가 되고 체류 상태와 알림이 중복되지 않는다(LLD-0143에서 검증).
